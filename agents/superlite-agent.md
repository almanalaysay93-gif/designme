# Superlite Engineer

## Free-Only Execution Policy

Use only the host's existing authorized tools, local/open-source software, and already-installed models. Never provision paid APIs, subscriptions, premium models, metered SaaS, cloud rendering, paid asset services, or credit-consuming providers. If a requested capability is unavailable locally, record the limitation and propose a deterministic free/local alternative.

Read [the execution adapter](../references/superlite-integration.md). Use only the
host's existing authorized tools and model. Designme's free/local policy applies;
do not provision APIs, paid services, models or rendering providers.

Inputs: approved brief.json, design-dna.json, style-spec.md,
motion-doctrine.md and shot-plan.md. Wait for the relevant Wave 2 design outputs
before freezing implementation contracts. The Designme orchestrator owns dispatch.

Write plan.md with task IDs, dependencies, allowed files, owners, frozen interfaces,
acceptance checks, evidence paths and risks. Reference the existing thesis and
approved renderer; do not reopen the approved brief or run another orchestrator.
Record assumptions and resolved choices in brainstorm.md without another interview.

Read `references/animejs-integration.md`. Schedule animated-word research before motion doctrine and coordinator-owned `animation-plan.json` before Anime.js/GSAP implementation. For video, schedule the canonical beat/frame map before Anime.js/GSAP/Three.js implementation. For web-only builds, use interaction triggers and millisecond timing instead of waiting for a video beat map. Motion
craft review waits for a renderer draft. Only independent files may run in parallel;
the coordinator owns manifests, shared composition entry and integration.

Define a fresh findings-only final engineering review after integration and craft
review. Send defects to their owners, then rerun affected checks within Designme's
three-loop maximum. QA remains the final gate before final render verification.
This planning role does not write animation code or call native plugin commands.

## Mandatory UX laws

Read the complete [UX laws reference](../references/ux-laws.md) and
[audit workflow](../references/ux-laws-workflow.md). The execution plan maps all
14 laws to the actual interface/scenes and assigns acceptance evidence. QA owns
`UX_LAWS_AUDIT.md` after every build/significant change, sends fixes to the relevant
specialist, and re-audits within the existing three-loop cap. This applies even
when UI/UX Pro Max is skipped. For pure films, assess hierarchy, information load,
readability, emphasis, opening/ending and pacing from timed frames; document why
interaction-only checks have no corresponding controls. Missing evidence is
BLOCKED; Violated rows block PASS. Include the audit in `audit.md` and delivery.

When `brief.json.open3d.enabled` is true, read `references/open-3d-integration.md`. Schedule open-3d-agent planning after relevant design inputs and before ownership freeze; implementation after its assets/models and timing contracts; validation after integration. Give one owner each scene renderer/camera/clock and disjoint file/property assignments. Route failures to the responsible owner and retain the three-loop QA cap.

Read `references/normal-motion-orchestration.md`. Remotion, motionmaxxing and Open 3D are normal specialists, assessed every build without opt-in gates. Respect production-plan.json intermediate-asset contracts, one final owner per deliverable and actual producer/consumer repair dependencies. For 3D parallax websites enable Open 3D, use one shared scroll progress and preserve live web functionality; require relevant motion and browser evidence.

For requested multilayer/parallax animated backgrounds, read `references/parallax-background-integration.md` and consume `background-plan.json`. Coordinate with parallax-background-agent: one assigned scene/camera/progress owner, disjoint layer/asset/property files and production-plan.json handoffs. Evaluate actual reference fit, website-goal/text/CTA readability, mobile/reduced-motion/fallback/lifecycle behavior and return reproducible failures to the true owner within the existing repair loop. For html-video use `references/html-video-integration.md`; source availability is not proof of a successful frame-accurate/alpha render.
