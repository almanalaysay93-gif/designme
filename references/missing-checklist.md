# Completion and dependency checklist

This is the current required coverage checklist, not a history of defects claimed fixed. [SKILL.md](../SKILL.md), [manifest.json](../manifest.json) and [workflow](workflow.md) define the four-wave schedule. All core roles produce their output or a concrete BLOCKED result under the explicit dispatch rules; optional decisions and supporting responsibilities stay recorded.

## Before implementation

- Wave 1 planner-griller approves the goal, thesis, audience, website/video deliverable, references, optional decisions and constraints.
- Wave 2 research/browser evidence precedes dependent Design DNA, exact tokens, visual style and motion doctrine. Source URLs/images must actually be inspected or explicitly unresolved.
- Freeze task dependencies, one file/scene/property owner, canonical timing, production asset metadata and target-aware token naming before consumers implement them.
- For a reference reconstruction, the requirements precede img2threejs production; the gated deterministic factory precedes Wave 3 scene integration.
- Verify existing installs and source/license/dependency readiness before downloading anything. Keep all paid provider/model/audio/billing paths disabled; no invented tools or runtime success.

## Integrated draft and motion

- Wave 3 producers deliver their actual source/assets before HyperFrames or website assembly. Supporting website capture waits for a ready page; consuming film assembly waits for captured footage.
- Keep one scene/camera/clock and canonical scroll progress; no conflicting engine property ownership. Preserve headings/CTAs, mobile framing, loading/posters, reduced motion and lifecycle cleanup.
- Every animation has a tested reduced variant and gsap-timeline-reduced.js, with motion-a11y.md PASS/FAIL evidence. No reduced parallax/infinite loop or autoplay >5 seconds; no >3 flashes/second, temporal contrast failure or lost focus.
- Inspect actual frames and interactive states, not just code. Agent Desktop native UI evidence and separate local DOM/render/performance measurements remain distinct. Missing required execution is BLOCKED.

## Final gates, in order

- Wave 4 Genjutsu refines the approved thesis against the integrated result. Retained motionmaxxing/craft/taste/background/Open 3D/browser and engineering reviews feed owner-specific repairs before acceptance.
- render-perf-budget-agent proves CSR/SSR/first paint, actual fallback and JS/GLB/Lottie sizes; record LCP <2.5s, CLS <0.1 and INP <200ms with honest method/estimate limitations. A cut plan does not make an unresolved exceeded budget PASS.
- Resolve all required motion-a11y/performance findings and complete UX_LAWS_AUDIT.md. Final qa-anti-slop PASS must identify the exact tested source revision and relevant visual/audio/viewport/deterministic evidence.
- For films, decode/dimensions/FPS/duration/audio, contact sheets and repeated render checks finish before export. For websites, retain functional interaction/measurement evidence without inventing film outputs.
- Repair only affected owners, rerun producer/consumer and accessibility/performance checks, and invalidate stale gate evidence after source changes. Keep the existing three-loop cap; unresolved FAIL/BLOCKED remains visible at the cap.

## Last-after-QA handoff

- token-handoff-exporter starts only after final QA PASS for unchanged tested output. No build/review agent follows a successful export.
- Complete /handoff/ tokens.json, motion-spec.json, normal/reduced timeline modules, resize/dispose scene, handoff.md, version/hash manifest, target-aware import helper and referenced dependencies/assets.
- Actual /buildme token/snapshot/consumer names must match; do not invent a universal token schema or require manual code/token reconstruction. Missing consumer contracts and unexecuted required import evidence fail export.
- Validate file closure, named imports, SSR/client lifecycle, reduced mapping, immutable version history and checksums before atomically publishing the latest release. Failed staging never replaces a valid handoff.
- Behavior-changing packaging returns to the affected owner/gates and restarts export last; a stale QA stamp cannot approve changed behavior.

## Speckit input lock before design implementation

Between the approved Wave 1 brief and Wave 2, require the five-file theme/design baseline and read-only reviewer result. Missing decisions stop as explicit OPEN QUESTION entries. First FAIL returns exact fixes to the builder; second FAIL requires user action under the separate two-attempt cap. Wave 2 must consume the reviewed/versioned decisions rather than invent a second design. Any risk acceptance remains scoped and never waives missing values or the existing final accessibility/performance/QA gates.
